#45 — ROSTER-AWARE MOCK-DRAFT AI (draftAI.js)
================================================================================
Opponents used to draft best-ADP-in-a-reach-window, ignoring roster construction
(hoarded RBs, skipped K/DST). Now they weigh remaining roster requirements +
positional needs + position caps against ADP (NFL) / category value (roto).

- NEW /draftAI.js — pure, dependency-free, unit-tested. Exports pickNflOpponent,
  pickRotoOpponent, nflOpenNeeds, nflPosCaps, rotoOpenSlots. NFL: open starter
  slots (QB/RB/WR/TE/FLEX), soft caps (K/DST=1, QB/TE=starter+1, RB/WR deep for
  FLEX/bench), must-fill switch late so every slot fills. Roto: each sport's
  slot-eligibility model. Preserves the long-standing ADP/board ordering + the
  pow(rand,1.6) reach window.
- fantasyedge-draft.html: bestForAI now derives the AI team's roster (from
  state.picks) and delegates to the module. Only opponent auto-picks changed;
  user suggestions/advise engine, scoring, board, UI untouched.
- Tests: scripts/test-draft-ai.mjs (npm run test:draft) — full simulated NFL
  (10x15) + NBA (10x13) snake drafts assert legal/realistic rosters, plus
  need/cap/must-fill unit checks. 7/7 pass. Plain-node pattern (no framework),
  matching scripts/verify-draft-coach.mjs.

#46 — RANKINGS PER-SPORT STAT HEADERS
================================================================================
Investigation: headers DO relabel via updateStatHeaders() — it writes h1..h8 by
COMPUTED id (getElementById('h'+(i+1))) + innerHTML <span class="th-lbl">, which is
why a literal-`h1` grep found nothing. STAT_HEADERS.pga already existed. The real
bug: updateStatHeaders() ran ONLY inside renderTable() (after the async fetch), so
applySport() left the previous sport's / static baseball labels showing during the
load window (reproduced: MLB->PGA kept h1="AVG" ~1.5s before flipping to SG:OTT).
Fix: one line — call updateStatHeaders() at the end of applySport(). Idempotent;
no change to sorting, data-stat/zkey bindings, or the combine checkboxes.

KEY TECHNICAL NOTES / GOTCHAS (carried forward)
================================================================================
- Deploy model: main IS the production branch — merging to main auto-deploys to
  PROD via Git integration (no separate promote step). `vercel deploy --yes
  --scope fantasy-edge-s-projects` makes a standalone PREVIEW (SSO-gated). CLI
  deploy w/o scope, and `--scope <personal>`, both error ("Not authorized" /
  "cannot set Personal Account as scope") — always use the team scope.
- Patchright harness route-order gotcha (bit me again): routes match
  LAST-registered-FIRST, so register the broad **/api/** catch-all BEFORE the
  specific **/api/sports** or the catch-all shadows it ({} -> renderInactive ->
  locked). Harnesses live in the session scratchpad.
- Search box listener is on KEYUP, not input/change — patchright fill() won't
  trigger it; use type()/pressSequentially() to exercise search in tests.
- Vercel "Sensitive" env vars are write-only (can't be pulled/read) -> Stripe
  price verification is impossible from this env; needs the dashboard or a
  restricted read-only key. (See notebooklm-auth-workaround memory for the other
  standing gotcha.)
- index.html and fantasyedge.html are byte-identical landing duplicates; keep them
  in sync (cp index.html fantasyedge.html after edits).
